    Type safety

    Three bugs TypeScript catches in this app once your types are in. With today's loose types, it catches none of them.

    A typo in a state name

    catalog.setState(() => ({ status: 'sucess', data }));

    TS2820: Type '"sucess"' is not assignable to type '"idle" | "loading" | "success" | "error"'. Did you mean '"success"'?

    In plain JS: no error. The render switch matches nothing, and the page stays on skeletons forever.

    A product that might not be there

    const product = byId(state.data, id);
product.price.toFixed(2);

    TS18048: 'product' is possibly 'undefined'.

    In plain JS: "Cannot read properties of undefined (reading 'price')", the moment a stale button is clicked.

    An element that might not exist

    const input = document.querySelector('#search');
input.value;

    TS18047: 'input' is possibly 'null'.
    TS2339: Property 'value' does not exist on type 'Element'.

    In plain JS: works until someone renames the id, then crashes on page load.
